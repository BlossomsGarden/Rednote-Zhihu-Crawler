# 从 JSONL 到调研报告

> 工具只负责采集、降噪和统计；结论仍需要人工阅读与归纳。下面是本项目使用的分析流程，不含任何真实数据或报告内容。

## 1. 先跑 Digest

```bash
python -X utf8 tools/digest_for_analysis.py data/batch50/xhs/r1 data/batch50/xhs/r2 > digest.txt
```

- 按帖子相关性排序，优先读前 30–50 条。
- 每条帖子保留 `URL` 与 `post_id`；评论保留 `cid`。
- 被过滤的低价值评论仍在原始 `comments.jsonl`，需要时可 `--include-low-comments` 回看。

## 2. 人工提取：一条信息一行

建议用表格或 Markdown 笔记逐条摘录，字段固定，方便后续归并：

| 字段 | 说明 |
|---|---|
| `公司` | 帖子明确提到的招聘方；未提到写“未提及” |
| `岗位 / 方向` | VLA、世界模型、灵巧手、数据、RL、Infra…… |
| `轮次` | 一面 / 二面 / 主管面 / HR 面 |
| `问题` | 尽量保留原话；同义问题可在归并时合并 |
| `答题要点` | 自己的答案骨架、关键数字、论文/项目素材 |
| `来源 URL` | 原帖链接，必填 |
| `cid` | 来自评论时必填，便于定位楼层 |
| `可信度` | 原帖 / 评论 / 转述 / 未核实 |

原则：

- **一条帖子可以拆成多条信息**，但每条都要能回到同一个 URL。
- 评论里的信息单独标 `cid`，不要只记“评论区有人说”。
- 数字必须带口径（成功率、样本量、评测条件）；没有口径的数字标注“帖子口径”。

## 3. 归并与计频

- 同义问题合并：如“Action Expert 为什么单独存在”和“为什么不在 VLM 上直接回归动作”算一类。
- 区分“公司原题”与“作者观点”：前者进题库，后者进趋势/判断章节。
- 按出现频率 × 区分度排序，而不是按帖子顺序。
- 保留矛盾：同一问题不同公司/面试官口径不一致时，写清两种说法，不要强行统一。

## 4. 报告结构（可复用）

```text
0. 一页结论
1. 岗位画像：招什么人、看什么
2. 公司 × 岗位 × 轮次明细
3. 通用题库（含基础八股）
4. 专项：π 系列 / 世界模型 / 灵巧手 / RL 后训练
5. 数据工程
6. 代码题 / 手撕
7. 面试感受、行情与避雷
8. 高频题优先级（S/A/B）
9. 反问清单
附录：公司清单、口径与不确定性、批次统计、逐轮笔记索引
```

每一节只回答一个问题；能在正文用表格的，不要写成大段散文。

## 5. 交付前检查

- [ ] 每个公司/题目条目都有 URL。
- [ ] 评论条目都有 `cid`。
- [ ] 低价值评论没有进入正文，附录写明过滤口径与占比。
- [ ] 帖子口径 vs 官方信息已区分。
- [ ] 图片帖未 OCR 的题目已标注。
- [ ] 统计表由 `report_stats.py` 重新跑过，数字一致。

## 6. 关于本仓库的报告

本仓库**不包含**真实采集数据与分析报告。上面的流程用于说明方法；完整数据与成稿报告不随仓库分发。
